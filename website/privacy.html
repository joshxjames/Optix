Privacy Policy

Effective date: 5 May 2026 · Last updated: 5 May 2026

This policy explains what data Optix collects, why, where it's stored, who else sees it, how long it sticks around, and how you can get rid of it. We've tried to write it in plain English. If anything is unclear, email admin@covetable.com.au.

1. Who we are

"Optix", "we", "us", or "our" refers to Covetable Pty Ltd, an Australian company that builds and operates the Optix desktop application and the Optix Cloud subscription service. You can reach us at admin@covetable.com.au.

2. What this policy covers

This policy applies to:

  • The Optix desktop application for Windows, macOS, and Linux.
  • The Optix Cloud subscription service (managed Anthropic relay).
  • The Optix marketing website at optix.app.
  • The Optix support form (in-app and on the website).

It does not cover the third-party services you may choose to use through Optix — those have their own privacy policies. We list them in section 7.

3. The TL;DR

  • The Optix desktop app stores almost everything locally on your machine — settings, audit logs, conversation history, recorded routines. We don't have a copy.
  • API keys for any provider you bring (Anthropic, OpenAI, Kimi, Gemini) are stored in your operating system's keychain, encrypted at rest by your OS.
  • When you send a prompt, the prompt and any screenshot go to whichever model provider you chose. That's the whole point of the product.
  • If you subscribe to Optix Cloud, requests pass through our relay on the way to Anthropic. The relay never logs prompt content or model output; it only counts tokens for billing.
  • The marketing website has no analytics, no trackers, no cookies, no advertising pixels.
  • You can delete any local data from inside the app, and request full account deletion by emailing us.

4. What we collect, why, and where it lives

4.1 What stays on your machine

The Optix desktop app stores the following inside your operating system's standard application data directory (Windows %APPDATA%\optix.desktop\, macOS ~/Library/Application Support/optix.desktop/, Linux ~/.config/optix.desktop/):

  • Settings — your active provider, model preferences, hotkey, approval mode, cost ceiling, workspace folder, theme. No identifying information.
  • Widget window position — so the widget reopens where you left it.
  • Audit logs (Access mode runs) — for each Computer Use session: your initial prompt, every model turn, every action the agent took, the actions' outcomes, token usage, and the estimated cost. Stored as JSON, one file per run.
  • Conversation history (Ask mode) — saved Q&A turns, plus any image attachments and screenshots that were part of those turns.
  • Recorded routines (Automate mode) — the action sequence you recorded, plus the original prompt and metadata. Replayable later.
  • Active plan — when you use the planning tool, the approved plan persists so the agent can resume.

Your API keys for any model provider you configure (Anthropic, OpenAI, Moonshot/Kimi, Google Gemini) are stored in your operating system's keychain — Windows Credential Manager, macOS Keychain, or Linux libsecret/GNOME Keyring. They are not in any plaintext file we control. The Optix process briefly caches them in memory to make API calls (5-minute TTL) and drops the cache on app exit.

We do not have access to any of the data above. It does not leave your machine unless you explicitly use a feature that sends it somewhere (next sections).

4.2 What goes to your model provider

When you submit a prompt, the following is sent to whichever provider you've selected (Anthropic, OpenAI, Kimi, Gemini, or Optix Cloud):

  • Your prompt text.
  • A screenshot of your active window (unless Privacy Pause is on; see section 8).
  • Any images you attached to the prompt.
  • In Access and Automate modes, conversation history for the current loop, plus the contents of any files the agent reads via tool calls and the output of any shell commands it runs.

Each provider has its own privacy policy and data-handling terms — see section 7.

4.3 What goes to Optix Cloud (only if you subscribe)

If you subscribe to Optix Cloud, your prompts pass through our relay (a Firebase Cloud Function) on the way to Anthropic. We architected the relay to handle as little of your content as possible:

  • The request body is forwarded byte-for-byte to Anthropic. We do not inspect, modify, or store it.
  • The relay does not log prompt text, screenshot bytes, or model output. Multiple comments in our source code enforce this; you can inspect the source code if you have access to the repository.
  • What we do store in Firestore: per-month token totals (input, output, cache-create, cache-read), request count, last-request timestamp. This drives the usage meter in Settings and enforces your monthly token allowance.
  • What's logged for diagnostics: error traces with your Firebase user ID only — never email, never IP for the relay path, never content.

4.4 Account information (Optix Cloud only)

To use Optix Cloud, you sign in via passwordless email magic link. We collect:

  • Your email address, used for the sign-in link and as your account identifier.
  • A Firebase user ID generated for you on signup.
  • Your display name if Firebase Auth derives one (typically empty).

Stored in Firebase Authentication and (mirrored) in a Firestore document at users/{your-uid}. BYO-key users (those using their own Anthropic / OpenAI / Kimi / Gemini key) never sign in and never have an account with us.

4.5 Billing information (Optix Cloud only)

Subscription billing is handled by Stripe. When you subscribe:

  • Stripe collects your payment method, billing address, and any 3DS challenge data. We never see your card number — Stripe's hosted checkout page handles it directly.
  • Optix's backend stores your Stripe customer ID, subscription ID, plan tier, billing period end, and subscription status in your Firestore profile. We use these to enforce your token allowance and show your plan in Settings.
  • Stripe webhook events update your subscription status and tier when you upgrade, downgrade, cancel, or your card fails.

4.6 Support form submissions

If you submit the in-app or on-site support form, the submission is sent to admin@covetable.com.au via SMTP. The email contains:

  • Anything you typed: name, email, subject, message, topic.
  • Diagnostic info auto-included so we can reproduce issues: app version, browser/OS user agent, locale, your active provider (if signed in), your Optix Cloud account email (if signed in), your IP address, submission timestamp.

The Cloud Function that receives the submission does not store the body. It only logs whether the submission was authenticated and the IP address (used for rate limiting). The email itself is retained in our support inbox per Rackspace's mail-server policy.

5. What we do not collect

  • No analytics or telemetry. The marketing website at optix.app ships no Google Analytics, no Plausible, no Mixpanel, no Sentry, no Bugsnag, no anything. The desktop app sends no usage telemetry, no crash reports, and pings no update servers.
  • No cookies on the marketing site. The only browser-storage write is a localStorage entry remembering whether you picked light or dark theme. That's it.
  • No advertising IDs, no tracking pixels, no fingerprinting.
  • No selling of data. We do not sell, rent, or trade your data with anyone.

6. Third parties we send data to

This is the complete list. Each of these has its own privacy policy.

  • Anthropic — when you use Claude (BYO key, or via Optix Cloud). Anthropic privacy policy.
  • OpenAI — when you use OpenAI as your provider with your own key. OpenAI privacy policy.
  • Moonshot AI (Kimi) — when you use Kimi as your provider. Moonshot AI.
  • Google AI / Gemini — when you use Gemini as your provider. Google AI terms.
  • Firebase / Google Cloud — hosting for our relay and authentication backend (Optix Cloud users only). Firebase privacy.
  • Stripe — payment processing for Optix Cloud subscriptions. Stripe privacy policy.
  • Rackspace Email — receives our support inbox traffic. Rackspace privacy statement.
  • DuckDuckGo — used as a web-search fallback when the model needs current information and your provider doesn't have native search. We send only the search query. DuckDuckGo privacy policy.

We do not currently use any other third-party processors.

7. Where data is processed

Optix Cloud's relay and Firestore data are hosted in Google Cloud's us-central1 region (Iowa, USA). The desktop app keeps everything else on your local machine, in whichever country you're in.

If you're in the EU, UK, or other jurisdictions with data-export rules: by using Optix Cloud you consent to your account data being processed in the United States. If this is a problem for you, please email us before subscribing — we'll discuss whether it makes sense for you to use Optix Cloud or stay on BYO-key (which keeps everything on your device + with your chosen provider).

8. How long we keep your data

  • On your device (settings, audit logs, conversations, routines, plans, OS keychain entries) — kept indefinitely until you delete it. The app has UI to delete each one individually.
  • Firestore profile + usage counters — kept for the lifetime of your account. Deleted when you delete your account (see section 10).
  • Firebase Authentication record — kept until you delete your account.
  • Cloud Function logs — kept ~30 days (Google Cloud Logging default retention) and contain no content, only error traces and user IDs.
  • Firestore automatic backups — Google Cloud's default ~7-day point-in-time recovery window.
  • Stripe — Stripe retains payment records per their own policy and per applicable financial regulations (typically 7 years for PCI compliance). When your account is deleted, your subscription is cancelled but Stripe's invoice history persists on their side.
  • Support emails — retained in our Rackspace inbox per their default retention. We don't auto-purge.

9. Privacy controls inside the app

  • Privacy Pause — toggle in the widget. While paused, screen-capture is disabled. The agent can still answer follow-up questions but it can't see your screen.
  • Approval modes — choose per-action approval, per-task approval, or "trust inside the workspace folder". Out-of-workspace shell commands and file operations always require explicit approval, regardless of mode.
  • Workspace folder — set a directory the agent can read and write within. Anything outside it requires per-action approval. Cleared on every app start (does not persist across launches).
  • Cost ceiling — USD-denominated cap per Access run. Stops the loop if estimated spend would exceed it.
  • Per-feature deletion — Settings has separate UI to delete individual audit logs, conversations, routines, the active plan, and stored API keys.

10. Your rights

Under Australian Privacy Principles (Privacy Act 1988) — and in line with GDPR / UK GDPR / CCPA principles — you can:

  • Access a copy of the personal information we hold about you. Email admin@covetable.com.au and we'll respond within 30 days. (For most data this is just your Firestore profile and usage counters; on-device data is already in your hands.)
  • Correct inaccurate information. Same email address.
  • Delete your account and all associated data. Email us and we'll delete your Firebase Auth record (which automatically purges your Firestore profile, your usage counters, and immediately cancels any active Stripe subscription). On-device data is yours to delete via the app's UI.
  • Export your data. Audit logs, chat history, and routines are stored as JSON on your device — you already have the files. For your Firestore profile, ask via email and we'll send it to you.
  • Object to processing or complain to the Australian Office of the Australian Information Commissioner (oaic.gov.au) or your local equivalent.

11. Children's privacy

Optix is not directed at children under 16. We do not knowingly collect data from children. If you believe a child has used Optix Cloud and given us their information, please email us and we'll delete it.

12. Security

We follow industry-standard practices:

  • API keys are stored in your OS keychain, never in plaintext files we control.
  • All network traffic is over HTTPS (TLS 1.2+).
  • The desktop renderer is sandboxed (Chromium contextIsolation: true, sandbox: true, nodeIntegration: false); only a narrow, validated IPC surface is exposed.
  • Cloud Function endpoints verify Firebase ID tokens before processing requests; rate-limiting and honeypot defenses are applied to public endpoints.
  • Our codebase has been through nine rounds of internal security audit and hardening, with the audit log available on request.

No system is perfectly secure. If you discover a security issue, please email admin@covetable.com.au rather than disclosing it publicly.

13. Changes to this policy

When we update this policy materially, we'll update the "last updated" date at the top of the page and, for active Optix Cloud subscribers, send an email summary of the changes. Continued use of Optix after changes are posted means you accept the updated terms.

14. Contact us

For any privacy-related question, request, complaint, or just to ask what we're doing with a piece of data: admin@covetable.com.au.
